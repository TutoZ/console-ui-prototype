# 京小灵主框架契约｜新功能必须接入的共同结构

0.2 分层索引：本文件保留 F01–F08 明细；产品级入口为 [product.md](product.md)，业务解释归 [domain.md](domain.md)，视觉绑定归 [design.md](design.md)。

状态：基于当前代码整理现有结构；F01–F08 为建议采用的统一约束。不是全平台重构指令。

## 1. 现有框架与新功能归属

| 层 | 当前承载 | 新需求放置原则 |
|---|---|---|
| 平台与团队 | 登录/团队选择、账号管理、角色权限、资源中心 | 团队隔离和权限沿用统一机制；不在业务页另造账号系统 |
| 数字员工 | Agent Builder、我的数字员工、市场、技能 | 跨业务的身份、雇佣、岗位能力与共用资源从这里管理 |
| 业务域 | 在线客服、外呼、热线、电销、随访、催收、质检 | 特定业务任务在对应域执行，不能每个域重建“我的员工”主对象 |
| 员工工作区 | 入职培训、派出渠道；知识/技能在培训内配备 | 配置、测试、存档围绕同一员工；区分编辑态与运行态 |
| 任务与结果 | 任务下发、监控、记录、业绩、客服工作台 | 保持员工、任务、会话、版本之间的可追溯关联 |

导航依据：`lib/navDomain.ts`、`docs/nav-ia.md`、`src/App.tsx`。全局框架不得随单功能生成而重画。已有多版导航，试点须记录实际启用的版本。质检目前绕过通用员工培训工作区；不能把在线客服示例直接套给质检。

## 2. 三条贯通链路

- 员工生命周期：选择/创建 → 雇佣 → 培训 → 测试 → 上岗 → 工作 → 复盘 → 再培训。
- 工作任务：表达目标 → 补充必要信息 → 确认范围 → 执行 → 人工介入/恢复 → 交付 → 验收。
- 能力演进：反馈 → 草稿修改 → 保存候选存档 → 同版本测试 → 确认应用 → 跟踪效果。

第一条来自现有产品组织，后两条是统一框架建议。跨域可裁剪，但必须说明跳过哪些阶段、原因是什么、如何保障同样的控制与验收要求。

## 3. 核心对象：用业务对象组织功能

| 对象 | 最低标识与关系 | 不能混淆 |
|---|---|---|
| 团队 | teamId，成员与权限 | 同名员工不代表同一团队对象 |
| 员工 | employeeId，岗位、所属团队 | 员工身份不等于一个培训版本 |
| 培训存档 | snapshotId，员工、配置及依赖版本 | 已保存不等于已生效 |
| 测试记录 | testRunId，snapshotId，测试集/环境、结果 | 对话发生过不等于测试通过 |
| 工作任务/会话 | taskId/sessionId，员工、使用版本、状态 | 员工在岗不等于每个任务都在运行 |
| 结果/日志 | resultId/eventId，任务、时间、来源与状态 | 动画和生成文案不等于真实执行证据 |

这些是跨页关联的逻辑要求，不要求前端现在已有全部字段。研发设计接口时再映射具体字段，不能拿本地存储代替服务端隔离与权限。

## 4. 框架规则

| ID | 必须满足 | 验证问题 |
|---|---|---|
| F01 导航与上下文连续 | 复用现有外壳，保留团队/员工/业务域；返回后保留可恢复的列表条件 | 从记录进入详情再返回，能否继续原任务？ |
| F02 对象关联明确 | 操作绑定稳定对象 ID；关键页显示对象名与当前版本/范围 | 同名员工、切换团队会否操作错对象？ |
| F03 状态分层 | 分开员工在岗状态、任务状态、培训状态和测试状态 | 是否出现“测试中”让线上员工被误解为停止工作？ |
| F04 变更与控制生效 | 区分请求中、成功、失败、结果未知；成功依真实回执 | 超时后是否错误显示成功或允许重复提交？ |
| F05 过程与结果可追溯 | 结果连到任务和使用版本；日志注明时间、来源、真实/模拟 | 复盘能否定位当时使用的配置？ |
| F06 能力变更有边界 | 草稿、测试、应用分开；明确哪些对象和新旧任务受影响 | 保存或预览是否会悄悄改线上？ |
| F07 统一组件与术语 | 引用现有设计系统、共享组件、词表；冲突登记 | 新功能是否新增同义入口或自造状态色？ |
| F08 权限与恢复完整 | 无权限仍解释状态；关键操作后端校验；异常保留有效输入 | 隐藏按钮后，其他入口是否仍可越权操作？ |

## 5. 动态交互规则：按状态组织，不让生成破坏框架

| 条件 | 界面响应 | 稳定不变的部分 |
|---|---|---|
| 意图缺少决定性信息 | 显示必要补充项，说明为什么要填 | 当前员工、业务域、已输入目标 |
| 草稿有修改 | 显示未保存状态、差异摘要和保存入口 | 当前上岗存档与在岗状态 |
| 已保存但未测试 | 引导能力测试，解释不能应用的原因 | 保存记录、目标存档 ID |
| 测试失败/部分完成 | 显示失败项、已完成项、重试/修正入口 | 原始输入与测试记录 |
| 候选通过 | 显示变更摘要、适用范围、应用入口 | 主导航与员工身份 |
| 应用中/结果未知 | 锁定重复提交，显示确认进度或查询入口 | 原版本与请求标识，直到真实结果确认 |

AI 可以生成说明、推荐补充项和结果摘要；权限、状态含义、应用条件及固定操作不可由模型自由改写。生成信息缺失或矛盾时降级到确定表单和已知状态，不编造完成情况。键盘焦点不因流式内容插入而跳转，用户已填项不被自动覆盖。

## 6. 视觉与组件继承

引用根目录 `DESIGN.md`、`lib/ui.ts`、`src/index.css`、`docs/component-library.md`；操作接口以实际组件源码为准。文档冲突时记入缺口，由设计师裁定语义，已有源码用于确认当前行为，不自动把历史缺陷升为新标准。

| 场景 | 首选现有资源 |

| 培训存档 | AgentVersionPanel / src/lib/agentVersions.ts |
| 能力测试 | OnboardingCapabilityTestPanel / ExecutionProcessFold |
