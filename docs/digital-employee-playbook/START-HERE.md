# 京小灵 Vibe Design｜通用 AI Coding 入口

这是工具无关的项目指令。Cursor、Codex、AI Studio 或其他 AI Coding 工具均使用同一份设计知识；工具专属规则只负责引导到这里。用户只需输入需求，不需填写 JSON、选择组件或执行命令。

## 首次接入：先检查可用能力

读取当前项目，报告能否读取工作包、组件源码与样式，能否修改代码、运行检查和打开预览。只报告实际能力，不能把知道文件名当成已读文件。

- 有完整项目：按下面流程实现和验证。
- 只有规则文档，没有组件源码或可用组件包：可做 Spec 与结构方案；列出缺失实现资产，不声称已复用真实组件。
- 能生成与预览，但无法运行检查：继续生成可交互结果，保留本次 Spec、绑定和检查清单；导出代码后在具备环境的工具中补验，结果标记待验证。

“任意工具”指入口可适配，不代表所有工具具备相同执行能力。不要为适配工具而降低最终体验验收标准。

## 每次需求

1. 理解用户、对象、目标、约束、不做事项与框架位置。按 product.md 和 domain.md 的当前域确定主线；缺规则不自动套用在线客服。
2. 输出简短设计理解，按 templates.md、components.md、design.md 和 craft.md 形成 Spec，使用真实组件和 Token。只读取相关知识。案例是判断来源，不是把所有历史要求一起执行。
3. 按小交互单元实现，连接完整任务；覆盖默认、等待、成功、失败、只读等适用状态。布局与反馈沿用已有模式，新模式说明依据。
4. 有执行环境时使用 09-execution-guide.md 的建档、绑定与评估命令；没有时输出相同字段的材料，保留未执行状态。结构化产物由助手制作。
5. 实际查看 UI、操作路径、两种宽度及键盘交互；记录观察、截图、失败和修复。证据未齐不宣称合格，代码变更后复验。
6. 交付可打开的 UI 和交互、简短验证结论与未完成项；将可复用经验写回所属知识层。保留原项目改动，不添加需求外导航或功能。

知识路径均相对本文件目录。技术检查入口见 09-execution-guide.md；实际目录覆盖见 catalog.json。根品牌文档与源码冲突按 design.md 记录，不擅自重定义全局样式。
