# 六项体验主张｜从感受变成判断标准

0.2 分层索引：本文件保留六项主张明细；产品级任务与框架约束从 [product.md](product.md) 进入。

状态：保留用户原有六项名称，对执行边界作建议性细化。主张 ID 在 Spec、验收与问题单中保持稳定。

**总主张：让用户像管理员工一样，轻松委派工作、掌握进展、验收成果，并培养适合自己业务的数字员工。**

## 六项标尺

| ID / 主张 | 用户要得到什么 | 必须可观察到的行为 | 反例：不能这样判达标 |
|---|---|---|---|
| E1 轻松上手感 | 学得轻松、用得顺手、看得统一 | 入口清晰，业务语言可理解；主任务有下一步；空态能启动，错误能恢复；同概念同叫法、同操作同反馈 | 增加引导遮罩就算易用；复制视觉但漏掉异常状态 |
| E2 完全掌控感 | 看得见、管得住 | 当前状态、影响范围、控制操作清晰；确认后展示真实生效情况；不能立即中断时说明边界和处置方式 | 点按钮即显示成功；保存时静默替换正在工作的版本 |
| E3 踏实干活感 | 看见有效推进，结果可核验 | 关键执行事件、输入/输出依据、失败与未完成项可查；结果指标有口径、时间范围和样本量 | 用加载动画代表真实工作；把模拟日志、耗时长或处理量大当成果质量 |
| E4 真实拟人感 | 管理与交流自然，身份和职责清晰 | 岗位、雇佣、培训、上岗、汇报的心智一致；拟人语言准确映射动作与后果；明确是数字员工 | 用“休息”掩盖取消任务；为了拟人化把有清晰含义的业务术语全部替换 |
| E5 养成归属感 | 我教的内容可保留，变化可感知 | 能编辑培训要求，看到变更、存档、测试、应用范围；用相同样本比较前后表现；历史可追溯 | 保存配置就宣布“能力提升”；宣称所有对话都自动形成长期记忆 |
| E6 专业胜任感 | 知道它擅长什么，什么工作适合交给它 | 岗位、首要能力、依赖、限制与代表成果明确；超范围时说明不足并提供转交路径 | 用头像、人设或无依据的“专家”标签替代能力证据 |

## 主张如何分工

- 基线：E1，保证任务能开始、操作可理解。
- 信任：E6 回答“该不该交”；E2 回答“如何管”；E3 回答“干得怎样”。
- 长期协作：E4 让关系与沟通自然；E5 让培养投入可以保留和复用。

每个功能选 1–3 项主要主张，写成具体规则。其余主张是不能破坏的基线；不适用项写原因，不为凑六项而添加头像、成长数值或多余面板。任何涉及执行/发布的功能必须评估 E2，涉及结果的功能必须评估 E3，涉及能力变更的功能必须评估 E5/E6。

## 冲突时如何取舍

1. 状态与结果真实、用户控制权、业务权限优先于拟人表达和视觉效果。
2. 高频路径优先简洁；变更后果、阻断原因、下一步不能被折叠隐藏。
3. 过程默认展示摘要；按需展开输入、调用的资源、执行事件和结果依据。不声称能够展示模型完整内部思考，也不编造过程。
4. 成长用可比较任务结果说明。前后模型、知识、测试集不同则标注，不能直接得出培训导致提升的结论。
5. 现有术语/组件不满足语义时，提交具体冲突和候选规则；不通过全局文本替换“修复”业务含义。

## 不把假设当调研结论

本包沿用用户提出的焦虑与主张，未新增用户访谈证据。试点访谈验证：用户能否说清当前谁在接待、哪版生效；能否解释保存/测试/应用的区别；遇到失败是否知道下一步。记录真实行为与原话，再决定是否调整命名和交互。
