# 跨工具使用｜一次接入，日常只提需求

工作包服务于任意具备相应能力的 AI Coding 工具，包括 Cursor、Codex 和 Google AI Studio。设计知识、组件与验收标准保持同一份，工具只负责读取和执行。

## 组内同学的使用流程

1. 在自己熟悉的工具中打开组内维护的项目副本或已配置工作包的起始项目。
2. 首次确认助手能读取工作包及真实组件；若没有自动加载规则，粘贴下方启动语。无需每次重新配置。
3. 直接描述需求，AI 理解目标、形成 Spec、使用模板和组件、生成 UI 与交互。
4. 打开结果查看，继续用自然语言反馈；AI 按相同规则调优和验证，给出已通过与未完成项。

“只输入需求”是完成一次接入后的日常体验。维护项目、组件与规则版本由工作包维护者负责，不转嫁给每位同学。

## 不同工具怎么接入同一个入口

| 工具 | 本工作包的接入方式 | 首次检查 |
|---|---|---|
| Cursor | 项目 .cursor/rules/jxl-design-io.mdc 引导读取 START-HERE.md | 能读取规则正文、组件实现与样式 |
| Codex | 根 AGENTS.md 引导读取 START-HERE.md；项目 Skill 补充执行细节 | 当前项目及所需文件处于可访问范围 |
| AI Studio Build 或其他云端工具 | 在该工具可用的项目／指令上下文中提供 START-HERE.md 和所需资产；不假定自动读取 .mdc 或项目 Skill | 项目文件、依赖、预览和检查能力逐项核实 |
| 未自动识别规则的工具 | 使用通用启动语显式指定入口 | 助手列出实际读取的文件及缺口 |

AI Studio 的具体文件导入和项目能力以当前界面为准。官方文档说明可以导出 ZIP 或使用 GitHub 相关能力；不能由此推断它自动识别本包的规则文件或可以无差别运行本地 Python／浏览器脚本。跨工具导出后保留目录与依赖关系，在具备相应能力的环境中补验。[Google 官方说明](https://ai.google.dev/gemini-api/docs/aistudio-build-mode)

Cursor 支持项目规则，Codex 支持 AGENTS.md；这些是工具入口机制，不能替代实际加载检查。[Cursor 官方规则](https://cursor.com/docs/rules)、[Codex 官方指令](https://developers.openai.com/codex/guides/agents-md)

## 可复制的首次启动语

> 请使用项目中的 docs/digital-employee-playbook/START-HERE.md 作为京小灵设计交付入口。先核对你能读取的规范、真实组件和样式，以及能执行的预览和验证方式。之后我只输入需求，你负责理解、生成 Spec、选择模板、复用组件和 Token、实现 UI 与交互并验证。不要求我填写 JSON 或挑组件。缺失资产与未执行检查明确说明，不假装已接通。

如果工具中没有这个文件，先将工作包及对应项目资产放入它可读取的位置，再指向实际入口。不能只粘贴电脑上的绝对路径，期待云端工具读取本地磁盘。

## 维护者需要提供的资产

通用入口、六层知识、catalog 与原子用例；当前任务需要的共享和业务组件及其依赖；lib/ui.ts、全局样式、字体图标等实际资源；项目依赖与构建配置；选定的参考案例和验证工具。仅有 Markdown 规则不足以保证真实组件复用。

按任务选择资产，避免将全部聊天导出、凭据或无关数据当成必需上下文。跨工具使用同一版本，记录本次规则和源码版本，不为每种工具另维护一套设计标准。

## 能力不足时仍按同一标准交付

能预览但不能跑命令：交付可交互原型与未执行清单，导出后补绑定、类型和行为检查。能写代码但不能看画面：视觉仍待验证。组件缺失：先补资产，不将仿写外观标记为真实复用。完整验收可以跨工具接续，不能在缺少证据时降低为“看起来完成”。

目前本包已有 Cursor／Codex 的文件入口和本地试跑；AI Studio 提供的是接入方案，尚未完成该平台实机迁移验证。
