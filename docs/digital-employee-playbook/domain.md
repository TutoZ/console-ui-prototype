# domain.md｜业务级知识：用明确边界保护需求主线

版本 0.2 · 维护：业务产品经理，研发验证运行语义。当前首个完整域为在线客服培训；其他业务域仅登记范围，缺规则时不借用。

## 1. 加载方式

规划读取“共性边界”和恰好一个业务域。若任务跨域，先拆分工作单元，每单元分别写输入/输出、关联 ID 和数据交接；不把几个域的流程拼成一个模糊页面。

知识类型：OBS 为本地观察、DOM 为建议业务契约、GAP 为未补齐知识。DOM 的采纳状态见试点决策，默认不是生产承诺。

## 2. 共性边界

- DOMAIN-01：区分员工身份、在岗状态、任务状态、能力配置和测试资格；同一个“通过”必须说明通过什么。
- DOMAIN-02：所有动作绑定团队、对象 ID 和权限；界面词相似不代表权限相同。
- DOMAIN-03：结果未知独立于成功/失败；重复执行、并发更新、生效范围由业务契约确定，模板不得补造。
- DOMAIN-04：业务阈值需有来源、适用场景、版本和责任人；没有阈值时报告待定，不随机写 80 分/95% 即通过。
- DOMAIN-05：模拟数据只验证交互；模型、知识和规则版本不同的结果不能直接证明培训带来因果提升。

## 3. online_service：在线客服培训与应用

现状 OBS-01：EmployeeManagePage 的保存处理更新 publishedSnapshotId；OBS-02：OnboardingCapabilityTestPanel 使用模拟回复；OBS-03：历史存档可查看/应用。来源是本地静态阅读，不证明服务端已完成版本隔离。

| 业务术语 | 精确定义 | 不能推导 |
|---|---|---|
| 保存培训 | 固化候选配置，生成可引用的存档 | 不能推导线上已应用 |
| 能力测试 | 针对固定存档和依赖执行带检查点的样例 | 不能把有回复当通过 |
| 测试通过 | 所有必需检查点有合格证据，且证据对应当前组合 | 不能证明全部真实场景都胜任 |
| 完成培训 | 结束本次培训工作区操作 | 不能暗含上岗或替换现有版本 |
| 应用候选 | 经授权，将合格存档用于约定范围 | 不能更新所有正在进行的会话 |
| 回退 | 将历史目标重新按当前资格检查后应用 | 不能绕过权限、依赖和证据条件 |
| 存档非当前 | 不是此刻应用的版本 | 不等于证据失效、员工离岗或存档过期 |

### 建议契约与规则来源

| ID | 精确规则 | 关联 Spec | 不允许的跨域借用 |
|---|---|---|---|
| DOM-OS-01 | 保存候选不更新在岗版本、当前会话或在岗状态 | R01 | 不借外呼“任务启用”语义 |
| DOM-OS-02 | 测试绑定存档、知识/技能、模型、测试集、评价规则版本 | R02–04 | 不借质检分数作培训资格 |
| DOM-OS-03 | 应用资格含同版本有效测试、无脏草稿、非预览、权限、依赖就绪 | R05 | 不把营销转化率作通过条件 |
| DOM-OS-04 | 确认应用后服务端回执决定状态，新会话生效、旧会话保持原版 | R06–08 | 不把“停止外呼”方式套入旧会话处置 |
| DOM-OS-05 | 幂等和并发校验必须覆盖所有入口；结果未知先查原请求 | R09 | 不使用随机前端延迟证明后台幂等 |
| DOM-OS-06 | 回退重复资格检查，预览只读，当前存档不能删除 | R10 | 不用“历史”推导无风险 |
| DOM-OS-07 | 权限在服务端复验；演示资格不得用于生产 | R11–12 | 不能以“管理员”文案代替授权 |

完整状态与失败恢复引用 05-training-spec.md；本文件负责确定业务解释，不重复完整页面表。

### 字段与决策最低集

employeeId/teamId、draftRevision、candidateSnapshotId、activeSnapshotId、testRunId、configurationFingerprint、applicationRequestId、expectedActiveSnapshotId。每个 API 都要注明必填、权属校验、未知结果如何查回。

当前待生产确认：版本绑定后端能力、历史数据迁移、真实测试集与抽检方法、角色能力映射、超时策略。允许开始隔离原型；不能让模板补出后台已存在的事实。

### 正反例

意图“先把新培训内容存下来”→只采用 DOM-OS-01，选择候选保存单元；不加载应用执行规则作为自动后续动作。
意图“让已通过的 V2 接待新客户”→采用 DOM-OS-03/04/05/07；执行前检查资格并确认范围。
意图“看以前 V0 的要求”→DOM-OS-06 只读预览；不能默认为回退。

## 4. 其他业务域登记与隔离

| domain ID | 当前源码入口 | 已知内容 | 本包未定义、不能猜 |
|---|---|---|---|
| quality_inspection | QualityInspectionPage / QcWorkspacePage / lib/navDomain.ts | 有质检计划、标准、数据及独立培训路径 | 评分阈值、复检流程、纠错生效、申诉权限 |
| outbound | OutboundOpsViews / DomainOpsPage | 任务、监控、培训、记录、业绩 | 停止是否中断正在通话、拨打时段、重拨和计费 |
| hotline | DomainOpsPage 的热线分支 | 培训、业绩、接待、号码 | 号码与渠道生效、通话接管与版本策略 |
| collection / telesales / followup | DomainOpsPage / CollectionOpsViews | 对应域导航与任务入口 | 案件/销售/随访政策、合规边界、有效结果口径 |
| platform | 员工市场/团队/技能等 | 跨域身份和资源入口 | 雇佣收费、套餐权益、资源审批与外部调用限制 |

对已登记但规则不足的域，输出 GAP-DOMAIN、当前可复用的结构候选以及需要产品经理补的字段；不可自动落到在线客服。全局默认业务域必须为空。

## 5. 新增业务域的最小模板

域 ID / 岗位用户 / 对象与关联 / 输入输出 / 关键动作 / 状态表 / 前置资格 / 权限 / 生效范围 / 不可逆动作 / 失败与重试 / 指标定义 / 正例反例 / 规则来源与确认人 / 可复用模板 / 最小验收用例。

新增规则先成为 proposed；经业务决策后记录 confirmed。产品级主线冲突回 product.md；业务规则缺失留在本文件；配色和组件接口不得在业务章节临时补充。

## 6. skill_creation：确认写入（设计策略提炼）

DOM-SK-01，proposed，来源 cases/02-aop-skill.md 与用户 Skill 设计策略：只有 AI 将修改当前 Skill 内容时出现写入确认；纯问答不触发。新方案出现后旧方案只读；确认前保留原内容；确认后在当前编辑位置更新。上下文为 skillId，不要求 employeeId。该规则不包含发布、员工创建或训练资格。试跑以演示数据验证交互，模型生成另接。

账号邀请与员工三栏案例目前为候选知识，尚无完整机器配方。遇到这类意图应读取对应案例及源码建立本任务规格，不能默认套用本节或在线客服培训。
