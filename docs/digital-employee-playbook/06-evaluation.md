# 验收机制｜以可复现证据决定放行

0.2 更新：本文件保留 P/I/B 与验收闸门；新增 [Design Evaluator](design-evaluator.md) 实行分层检查，先做 [原子用例](atomic-tests.md) 再做组合验证。

## 1. 三种验收，不能相互替代

| 层级 | 证明什么 | 所需证据 | 不能推导什么 |
|---|---|---|---|
| P 原型交互 | 主张对应的行为、状态和恢复可理解、可操作 | 按用例录屏/截图、固定模拟数据、状态记录 | 不证明真实权限、接口、模型效果、线上发布可用 |
| I 真实联调 | 真实系统遵守资格、版本隔离、权限、幂等和恢复规则 | 环境/构建号、请求回执、持久化与会话记录、实际操作 | 不证明大规模用户价值或长期业务提升 |
| B 业务试点 | 用户能完成任务，结果对实际工作有帮助 | 用户任务观察、任务样本、质量评审、指标口径和基线 | 小样本不能泛化为全平台结论或因果提升 |

每一层分别填写结论。P 通过、I 未执行，应写“原型交互通过，暂不具备真实上线证据”。

## 2. 交付闸门

- G0 规格可做：有业务输入、E/F/R/TC 对应；关键前置条件、生效范围、异常和模拟边界明确。业务未定项有责任人与处理方案。
- G1 原型可交：所有标记 blocking 的用例，其可见交互与模拟状态部分通过；非适用项由产品经理和设计师写明理由；关键体验项无失败、无缺证据。
- G2 可进入上线评审：全部相关联调用例通过，真实数据与权限、并发、资格和生效范围有证据；无 P0/P1 问题；上线审批沿用团队已有流程。
- G3 方法可推广：另一功能、另一名执行者复用本包完成交付，记录质量、导师介入和返工，不仅复现示例。

总体分数不能抵消阻断失败。没有工具/环境属于阻塞，有环境但未测属于未执行，两者都不能视为通过。所有例子初始均为未执行，不预填“通过”。

## 3. 体验质量检查

| 维度 | 检查问题 | 对应主张 |
|---|---|---|
| 任务与入口 | 用户是否知道从哪里开始、下一步做什么？ | E1/E6 |
| 语义与能力 | 岗位、依赖与限制是否准确，拟人词是否表达真实行为？ | E4/E6 |
| 控制与状态 | 当前、候选、预览和测试是否区分？失败/未知是否诚实？ | E2 |
| 结果与证据 | 是否能核对结果、版本、来源与未完成项？ | E3 |
| 培训与变化 | 保存、测试、应用关系是否清楚，变更效果能否比较？ | E5 |
| 框架与工艺 | 是否复用导航、组件、术语；键盘/窄屏是否可用？ | E1/F01/F07 |

每项给“满足 / 部分满足 / 不满足 / 不适用”，附一条证据和影响。不要求校招生发明一个无法解释的审美总分。原型规则通过后，可由设计师继续判断信息层级、反馈节奏、文案自然度，并把具体改进转为检查项。

## 4. 每次运行的证据模板

```text
功能 / Spec 版本：
构建号或代码版本 / 日期：
环境 / 角色 / 团队和员工测试 ID：
真实/模拟范围：
测试数据版本、依赖版本、复位方法：
评审者 / 执行者：
用例 ID：
实际操作：
预期结果：
实际可见结果及状态/副作用：
状态：通过 / 失败 / 阻塞 / 未执行 / 不适用
证据路径：〔录屏时间点、截图、请求回执或记录 ID〕
问题 ID / 严重程度 / 影响的 R-ID、E-ID、F-ID：
修正责任人 / 复验记录：
```

证据放在该功能交付目录的 evidence/ 中；一条用例可有多份证据，一张截图不得替代整个异步流程。涉及真实客户信息的证据使用脱敏数据与团队既有权限要求；本试点优先用合成业务数据。

## 5. 问题严重程度与回流

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 | 越权应用、跨团队数据错误、错误版本对外生效、真实重大副作用 | 阻断上线；确认影响并修复 |
| P1 | 主路径无法完成、保存丢失、假成功、无法恢复、关键状态误导 | 阻断当前对应层级验收 |
| P2 | 有可行替代路径的局部体验问题 | 明确影响、负责人和期限；产品/设计决定是否延期 |
| P3 | 不影响任务的工艺细节 | 进入体验优化清单 |

| 问题类型 | 回到哪份资产 |
|---|---|
| 不知道为谁做、怎样算成功 | 需求输入卡，由产品经理补齐 |
| 主张无法判断或彼此冲突 | 01 体验主张，由设计师补正反例 |
| 导航、对象、跨页状态断裂 | 02 框架契约 |
| 状态/异常/生效规则缺失 | 功能 Spec |
| 同组件/术语含义不一致 | 组件规范与平台词表，先明确正确语义 |
| Spec 清楚但行为不符 | 实现代码 |
| 判断只靠感觉、证据不足 | 验收用例和证据机制 |

修正规则后更新版本，并至少复验一个原失败样例与一个原通过样例。AI 连续两轮未解决同一阻断项时停止盲目生成，输出具体原因、最小复现与可选方案交给对应负责人，不通过降低标准结束循环。
