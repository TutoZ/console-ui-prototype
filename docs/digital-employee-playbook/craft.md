# craft.md｜通用交互工艺：每个小单元都要守住的规则

范围：跨产品可复用的表达与操作质量。此处不定义京小灵岗位规则、测试阈值、品牌色值或业务生效范围。

| ID | 规则 | 最小验证方式 | 失败回流 |
|---|---|---|---|
| CRAFT-01 | 一个局部区域只有一个明确主动作，结果和下一步能直接读懂 | 隐去说明演讲，观察用户能否找到动作 | 模板层级/Spec |
| CRAFT-02 | 触发后即时有响应，等待不抢焦点；未知进度不编百分比 | 固定慢响应，检查忙碌和键盘位置 | 组件/实现 |
| CRAFT-03 | 请求中、结果未知、成功和失败不同；错误有可行动恢复入口 | 分别注入明确失败与无终态 | Spec/业务规则 |
| CRAFT-04 | 失败保留有效输入，重试不重复副作用 | 单次失败后重试，核对输入及记录 | 实现/接口 |
| CRAFT-05 | 关键差异和影响在确认前可见，不藏在折叠内容里 | 只看确认层能否说清改变什么 | 模板/Spec |
| CRAFT-06 | 默认摘要、按需细节；日志来源可解释，不能编内部推理 | 核对每个展示事件是否有记录来源 | 数据/Spec |
| CRAFT-07 | 标签描述实际动作、对象和方向；禁用有原因 | 检查返回/交回/应用是否有明确目标 | 业务文案/组件 |
| CRAFT-08 | 所有关键操作键盘可达，焦点可见；弹层关闭恢复焦点 | Tab/Shift+Tab/Escape 实操 | 组件/实现 |
| CRAFT-09 | 状态不只靠颜色，错误与字段关联 | 读文字或辅助语义可理解状态 | 组件/实现 |
| CRAFT-10 | 窄宽、长名称、长错误不截断关键动作和信息 | 固定两种宽度和长内容测试 | 模板/样式 |
| CRAFT-11 | 空态说明原因和下一步，加载态不伪装无数据 | 切换加载/真空/筛选无结果 | Spec/组件 |
| CRAFT-12 | 生成内容插入时不覆盖用户输入，不改变既定主线 | 输入期间流式追加内容 | 实现/产品规则 |

## 最小交互单元

一个单元 = 一个明确前置状态 + 一个触发 + 一个首要断言 + 所需证据。可包含为完成同一个异步触发必需的等待/查询；多个业务动作拆开。例：“在岗 V1，有草稿；点击保存；断言 activeSnapshotId 仍为 V1”。另一个单元独立验证候选生成，不把两个断言塞入一条含糊通过结论。

按四层组织检查：

- L0 知识/路由：域与任务匹配、来源、Token引用。
- L1 单元：一个交互状态转换，优先覆盖负例。
- L2 组合：保存→测试→应用，检查单元接口和上下文是否连续。
- L3 任务：真实用户完成工作，验证理解和业务结果。

减少的是每次生成与测试的范围；保留 L2/L3，防止小单元都通过但整条任务断裂。交互遵从率 = 通过的适用原子单元 / 全部适用原子单元；未执行计入分母，不与代码测试通过率混算。

## 小单元生成顺序

先列断言和固定输入→选择承载槽位→复用组件→实现正常分支→注入一个异常→收证据→进入下一个单元。每次修复只带入关联 P/DOM/R/CRAFT 规则及组件，不重新附上整个业务知识库。

美观评审仍由设计师结合画面判断：层级、密度、节奏、排版、动效是否服务任务。静态检查无法替代截图与操作；未经观察的工艺项一律未验证。
